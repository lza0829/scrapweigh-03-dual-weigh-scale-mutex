# 旧物磅条（Scrapweigh）

骨架：过磅入站 → 品级锁价 → 结算关账 → 班次落印

- 前端 http://127.0.0.1:6700
- API http://127.0.0.1:11700
- 数据库环境变量 `SCRAPWEIGH_DB`（容器内默认 `/data/scrapweigh.db`）

```bash
docker compose up -d --build
```

## 同秤席位口径

本仓库全局采用 **席位牌排队后补落** 架构，不与“后到直接拒入”模式混用：

1. 数据库部分唯一索引 `uq_open_ticket_per_scale` 保证同一地磅最多一张状态为 `待定级/待结价` 的正式磅条。
2. 空秤过磅在同一事务内写正式磅条、毛/皮事件、地磅钉住、活跃态势占用段、直落席位牌和审计。
3. 同秤撞车的后到请求不写正式磅条、不改钉住，只写可核验的 `候席` 席位牌和领取事件；回执与 `/api/席位牌册` 均可核对。
4. 结价或销单后，正式磅条进入终态，地磅和占用段释放；再调用席位牌补落接口，按牌的请求快照生成下一张正式磅条。`幂等键/idempotency_key` 重放同一过磅回执，不重复发牌或落条。
5. 席位牌有 TTL，可通过 `/api/席位牌/超时作废` 扫描、牌面超时接口或读取册页/席位闸/总览时惰性作废；结局由 `seat_events` 重放。
6. 所有联动写入处于同一个 SQLite 事务；中途失败整体回滚，不留下幽灵席位牌、半截占用段或双正式未结票。

主要对读面：

- `POST /api/过磅` / `POST /api/过磅入口`
- `GET  /api/地磅席位闸`（别名 `/api/席位闸`、`/api/写闸`）
- `GET  /api/未结正式约束`
- `GET  /api/席位牌册`（别名 `/api/席位牌`）
- `GET/POST /api/席位牌/{编号或牌号}/重放`
- `POST /api/席位牌/{编号或牌号}/补落`（也支持 `POST /api/过磅/补落`）
- `GET  /api/态势占用段`（别名 `/api/占用段`、`/api/调度/占用段`）
- `GET  /api/对照?地磅编号=...`
- `POST /api/补称/{磅条编号}`
- `GET  /api/毛皮事件流水`
- `POST /api/地磅/{编号}/解钉`（也支持 `/api/过磅/串号解钉`）
- 既有 `/api/定级/{id}`、`/api/结价/{id}`、`/api/销单/{id}`、`/api/班次/{id}/落印`、`/api/审计`
